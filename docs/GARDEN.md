# Личный сад

Один календарный день с записью еды = один шаг роста. Количество ингредиентов,
КБЖУ и размер порции не ускоряют рост. Записи воды и категория drinks не дают
шагов. Используется существующее в дневнике понятие локальной даты записи.

Стадии авокадо: 0 / 3 / 7 / 14 / 21 день. В день завершения виден взрослый
экземпляр. Следующий день с едой начинает следующее авокадо; число выращенных
деревьев остаётся в коллекции. Дни не обязаны идти подряд.

Дни записываются в garden_days (составной PK user_id + day). Это постоянные
косметические начисления; удаление еды их не удаляет. При загрузке сада сервер
учитывает существующие записи еды до указанного сегодняшнего дня включительно.
Повторные запросы и несколько блюд не увеличивают счётчик за один день.
Пакетное начисление использует INSERT ON CONFLICT DO NOTHING.

POST /api/v1/tracker/garden/sync?today_str=YYYY-MM-DD возвращает только сад
авторизованного пользователя. Это POST, поскольку запрос синхронизирует ранее
сохранённые дни. Никаких данных еды/воды он не изменяет.

Неделя начинается в понедельник. Четыре дня с едой в одной календарной неделе
открывают керамическое оформление горшка навсегда. Это косметическая награда,
не требование есть определённые продукты. Открытый горшок отображается
в блоке награды; пользовательских уведомлений и списаний за пропуски нет.

Flutter обновляет сад при открытии дневника, возвращении приложения на передний
план, pull-to-refresh и изменениях записей. Сеть не подменяется оптимистическими
баллами: при ошибке показан последний полученный результат или кнопка повтора.
Движение растения учитывает Reduce Motion. Поддержаны RU/EN/KA и две темы.

Миграция: backend/alembic/versions/0003_garden_days.py, после
0002_add_auth_identities. Перед развёртыванием в другом окружении применить
миграции согласно фактическому состоянию Alembic. В текущей локальной БД создана
только новая таблица garden_days с checkfirst=True; остальные таблицы не менялись.
Существующий стартовый create_all также регистрирует модель через app.models.
