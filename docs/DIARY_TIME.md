# Местная дата дневника

Мобильное приложение использует часовой пояс устройства, а не язык интерфейса,
страну профиля или часовой пояс сервера. Доступ к геолокации не требуется.
Автоматическая смена региона следует системной настройке часового пояса телефона.

- Экран «Сегодня» переходит на новый день в местную полночь. При возвращении
  из фона дата проверяется сразу; изменения часового пояса в открытом приложении
  обнаруживаются в течение 30 секунд. Стрик и сад обновляются вместе с дневником.
- При просмотре истории выбранная дата сохраняется. Переходы между датами
  используют календарные дни, а не интервалы по 24 часа, включая переходы DST.
- Каждый новый запрос сохранения фиксирует UTC-момент начала операции
  (`X-Diary-Captured-At`) и местное смещение в минутах (`X-Diary-Offset-Minutes`).
  Координатор сохраняет оба заголовка вместе с ключом операции: повторы после
  полуночи, перезапуска или переезда используют исходный контекст времени.
- Фото еды и напитков получают местное время начала сохранения, даже если
  распознавание закончилось после полуночи. Пара «напиток + вода» имеет одну дату.
- Явно выбранная дата блюда/воды/веса сохраняется. Даты ISO с часовым поясом
  переводятся в переданный местный пояс перед записью в существующие naive-поля.
- Начисление дня сада проверяет местную текущую дату пользователя.
- Ответы старых запросов сада/стрика не заменяют результаты более новых запросов.

История хранится по календарным дням записи. При поездке прошлые блюда не
переносятся между днями. Миграция не требуется: старые записи не пересчитываются,
поскольку у них отсутствует достоверный исходный часовой пояс. Старые клиенты без
заголовков времени сохраняют совместимость (распознавание использует UTC).
Старые неподтверждённые операции без сохранённых заголовков также поддерживаются.

Проверки: `flutter_app/test/diary_clock_test.dart`,
`flutter_app/test/save_coordinator_test.dart`, `backend/tests/test_diary_time.py`.
Серверные тесты используют отдельную SQLite in-memory базу и заглушки AI.
