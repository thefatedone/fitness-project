# Разработка с обновлением на ходу и CI/CD

## Быстрый локальный цикл

Открой корневую папку `fitness-project` в VS Code. Запусти OrbStack, затем:

```sh
make dev
make dev-logs
```

Это пересоздаёт локальные backend/frontend-контейнеры в режиме разработки, используя
существующие PostgreSQL/Redis и тома данных. Не запускай это параллельно с важной
операцией в текущих контейнерах. Первый запуск веба устанавливает зависимости.
Контейнеры доступны в OrbStack как обычно; база остаётся доступной в DataGrip.

- Backend: сохранение `backend/app/*.py` вызывает Uvicorn reload.
- Веб: Next.js dev server применяет Fast Refresh после изменения исходников.
- Зависимости/Dockerfile: `make dev-rebuild`. Зависимости веба повторно устанавливаются
  в Linux-том; локальные macOS node_modules в контейнер не используются.
- Переменные окружения: пересоздай сервисы; миграции БД выполняются отдельно и
  автоматически при сохранении не запускаются.
- Возврат к обычной сборке: `make dev-standard`.

Настройки dev включаются явно через `docker-compose.dev.yml`; обычный
`docker compose up` продолжает использовать базовую конфигурацию.

## Flutter

Установи рекомендуемые расширения Dart и Flutter. В Run and Debug выбери
`NutriMind mobile (debug + hot reload)`, выбери устройство и нажми F5.
Необязательно запускать веб-контейнер, чтобы работать с мобильным клиентом.

В `.vscode/settings.json` включены автосохранение, hot reload и наблюдение за
внешними изменениями Dart-файлов, в том числе правками Codex. Не закрывай debug-сессию.
Если VS Code уже был открыт, выполни `Developer: Reload Window` перед запуском.

Hot reload сохраняет состояние, но не переисполняет `main()`/`initState()`.
Для таких изменений используй Flutter: Hot Restart. После изменения плагинов,
нативного кода, разрешений или compile-time defines нужен полный перезапуск/сборка.
Ошибки компиляции предотвращают успешный reload — смотри Debug Console.

В debug-настройках приложения выбери API для своей платформы:
- iOS Simulator: `http://localhost:8000`;
- Android Emulator: `http://10.0.2.2:8000`;
- физический телефон: LAN-IP компьютера и порт 8000, в одной сети.

Этот launch не добавляет OAuth client IDs. Если вход требует их, сохрани свою
действующую конфигурацию запуска с нужными dart-defines; секреты не добавляй
в общий launch.json.

## CI

Автоматический CI временно отключён: push и pull request больше не запускают
проверки из `.github/workflows/ci.yml`. Обычный push в `main` сохраняет код без
запуска этого workflow. Изменение вступает в силу после коммита и push обновлённого
файла. Результаты старых запусков остаются в истории GitHub Actions.

Конфигурация сохранена для дальнейшей настройки: её можно запускать вручную через
GitHub → Actions → CI → Run workflow. Она содержит три независимых задания:
backend pytest с одноразовыми PostgreSQL/Redis, веб lint/build, Flutter analyze/test.
Реальные ключи AI и рабочая БД не используются. Перед возвращением автоматического
запуска нужно устранить ошибки проверок и подтвердить успешный прогон.

## Следующий этап CD

Нужно выбрать хостинг backend/веба и канал мобильных сборок. Предлагаемая схема:
PR → CI → merge → staging → smoke-проверка → production с контролируемой миграцией
и возможностью отката. Для мобильного клиента — отдельные сборки и подпись,
затем TestFlight/внутренний канал Google Play или APK по выбранному сценарию.
В текущем Android release используется debug signing — для публикации нужна
настоящая release-подпись. Автоматический деплой и публикация пока не настроены.
